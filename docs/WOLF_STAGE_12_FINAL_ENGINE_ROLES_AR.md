**الحالة:** قرار معماري للمرحلة 12  
**الفرع:** `design/stage-12-final-engine-roles`  
**الأساس:** `feature/filament-offline-video-prototype`  
**نطاق هذه المرحلة:** تحديد الأدوار والملكية الفنية وحدود التشغيل وجاهزية كل محرك  
**دمج المحركات في مسار إنتاج الفيلم:** غير مشمول هنا؛ يظل الدمج الإنتاجي المضبوط مرحلة لاحقة مستقلة (مرحلة 15 وفق خارطة Stage 11)

## 1. القرار المركزي

يعتمد WOLF منظومة محركات متخصصة، لكن لا تصبح المحركات المتعددة هي مالك التطبيق أو خط إنتاج الفيلم. تظل طبقة Android Native المكتوبة بـKotlin هي المركز وصاحبة القرار النهائي.

تكون الملكية كالتالي:

1. **WOLF Kotlin Core / Motion Hub** هو مالك المشروع، والقصة، وتخطيط المشاهد واللقطات، والجدول الزمني، ومعدل الإطارات، وتزامن الصوت، وتوزيع الموارد، والاسترداد، وتجميع الطبقات، وفحص الجودة، وتصدير MP4.
2. **WOLF Motion Code Library** يوفّر الحسابات والمحاور والمنحنيات والتحويلات والتوقيت والدوال المشتركة المحايدة عن المحرك.
3. **WOLF Scene Contract** هو عقد البيانات الموحد بين المركز وكل محرك؛ لا تُمرّر كائنات محرك أو ذاكرته الداخلية مباشرة إلى محرك آخر.
4. كل محرك يعمل من خلال **Adapter مستقل** يترجم أوامر العقد إلى API المحرك، ثم يعيد مخرجات موصوفة بالتوقيت والأبعاد والصيغة والشفافية.
5. يختار Motion Hub محركًا أساسيًا واحدًا لكل مهمة/لقطة، ويضيف طبقات مساعدة عند الحاجة وبعد اجتياز حدود الموارد. لا يشغّل محركات 3D ثقيلة متعددة بالتوازي لمجرد أنها موجودة في التطبيق.

هذا القرار يحافظ على التطبيق الأصلي: فشل محرك أو مؤثر لا يوقف الفيلم كله، ولا يغيّر ملكية الجدول الزمني أو الصوت أو الحفظ أو نقاط الاستكمال أو مسار التصدير.

**قاعدة مدة التعليق الصوتي المعتمد:** عندما يعتمد المستخدم تسجيل الراوي، تكون مدته الفعلية المقاسة هي مدة الفيلم المرجعية. يمدّد WOLF تخطيط المشاهد واللقطات وعدد الإطارات أو يقلّصها لتغطية التسجيل كاملًا؛ ولا يُقصّ التسجيل ليطابق مدة مشروع منفصلة. إذا لم يوجد تسجيل معتمد صالح، يستخدم WOLF مدة المشروع المحفوظة.

## 2. مصفوفة الأدوار النهائية

| المكوّن | الدور المعتمد | حدود المسؤولية |
|---|---|---|
| **WOLF Kotlin Core / Motion Hub** | المدير المركزي وخط الإنتاج الأساسي | يملك القصة، اللقطات، الكاميرا على مستوى الخطة، التوقيت، الصوت، الذاكرة، الجودة، التركيب، الفصول، checkpoints وMP4. لا يتنازل عن هذه السلطات لأي محرك |
| **Godot 4.7.2** | محرك المشاهد ثلاثية الأبعاد العام والمضمّن | البيئات المعقدة، المشاهد متعددة العناصر، الشخصيات/المخلوقات، حركة العناصر والمشهد المكاني. ينفذ نية الكاميرا والحركة التي يرسلها WOLF ولا يصبح صاحب الجدول الزمني |
| **Filament 1.75.0** | محرك الرسم ثلاثي الأبعاد المتخصص بخامات PBR | لقطات GLB/glTF التي تحتاج خامات فيزيائية وإضاءة وظلال ومظهرًا ماديًا مضبوطًا، خصوصًا لقطات التفاصيل/الإدراج. لا يحل محل Godot كمدير مشهد عام ولا محل WOLF في الصوت أو الفصول |
| **libGDX 1.14.2** | طبقة رسم GLES منخفضة المستوى للمؤثرات البرمجية الخفيفة | مؤثرات 2D/متجهية/جسيمية محسوبة برمجيًا، sprites وحركات مخصصة صغيرة عندما تكون أخف وأنسب من تشغيل محرك مشاهد كامل. لا يملك إدارة المشهد أو الكاميرا أو التوقيت العام |
| **KorGE 6.0.0** | محرك مشاهد 2D بطبقات وParallax وانتقالات | المشاهد ثنائية الأبعاد المركبة، طبقات الخلفيات والعمق الوهمي والانتقالات التي تحتاج scene graph وواجهات Kotlin. دوره معتمد معماريًا لكنه غير جاهز للدمج حتى ينجح إثبات رسم إطار فعلي على Android |
| **Lottie Android 6.7.1** | الرسوم المتجهية والعناصر المتحركة فوق المشهد | شعار WOLF، بصمة الذئب، العناوين والبطاقات والانتقالات المتجهية المحددة مسبقًا. ليس محرك مشاهد 3D أو محرك تركيب الفيديو النهائي |
| **Cocos Creator 3.8.7** | دور مرشح ومؤجل للمؤثرات والجسيمات ثنائية/ثلاثية الأبعاد | لا يُعتمد للتشغيل أو الإنتاج الآن. يظل محجوبًا حتى توفير Creator 3.8.7 مرخّص، وتصدير Android native حقيقي، وبناءه وإظهار إطار مرسوم. Godot هو البديل المرشح المثبت حاليًا عند الحاجة إلى مشهد عام؛ ولا يعني ذلك أن Cocos اجتاز التوافق |
| **SceneView 4.70.0** | واجهة Android اختيارية للعرض/المعاينة فوق Filament | طبقة View/Viewer تسهّل عرض Filament داخل واجهة Android. ليس محركًا مستقلاً، ولا يضيف مالك كاميرا أو renderer ثانيًا |
| **Blender** | أداة إعداد أصول خارج التطبيق | إنشاء/تحرير النماذج والخامات والهياكل والتحريك والخبز والتحسين والتصدير إلى GLB/glTF. لا يُضمّن محرر Blender أو بيئة تشغيله داخل APK |

**حالة القرار:** الأدوار أعلاه هي التوزيع المعماري النهائي للمنظومة. اعتماد الدور لا يعني أن المحرك اجتاز كل اختبارات الجودة أو الأداء أو أصبح مدمجًا في نسخة الإنتاج. حالة الجاهزية أدناه هي المرجع عند تقرير الدمج.

## 3. قواعد اختيار المحرك لكل لقطة

- **مشهد 3D عام متعدد العناصر أو حركة مكانية معقدة:** Godot هو الاختيار الأول.
- **لقطة 3D متخصصة تعتمد أساسًا على خامات PBR وإضاءة/مظهر مادي لـGLB:** Filament هو الاختيار المتخصص.
- لا يُشغّل Godot وFilament باعتبارهما مالكين متوازيين للمشهد نفسه. يختار Hub محركًا أساسيًا واحدًا للّقطة، ويمكن تركيب ناتج محرك على آخر فقط عندما يحدّد العقد ذلك صراحةً وتسمح الموارد.
- **مؤثر برمجي صغير/خفيف:** يفضّل تنفيذ Kotlin القائم أولًا؛ يستخدم libGDX فقط عندما يقدم فائدة رسومية مثبتة لا يحققها المسار الأصلي بكلفة أقل.
- **مشهد 2D متعدد الطبقات أو Parallax يحتاج مشهدًا كاملاً:** KorGE هو المحرك المتخصص المرشح، بعد إثبات الرسم الفعلي والموارد.
- **شعار أو عنوان أو انتقال متجهي معروف مسبقًا:** Lottie.
- **Cocos:** لا يتم اختياره في وقت التشغيل ولا يدخل APK بوصفه محركًا معتمدًا ما دام وضعه BLOCKED.
- **SceneView:** يستخدم فقط عندما تكون هناك حاجة فعلية إلى واجهة معاينة Android فوق Filament؛ ولا يُضاف لمجرد تكرار قدرات العرض.
- **Blender:** مسار تطوير أصول خارج الهاتف، ثم تُراجع الملفات الناتجة داخل WOLF Asset Registry قبل السماح باستخدامها.

## 4. ملكية المشهد والكاميرا والزمن والتركيب

لا يملك أي محرك خارجي سلطة تغيير خطة الفيلم:

- StoryDirectorEngine يظل مسؤولًا عن نية اللقطة وتكوينها وتوزيعها على مستوى القصة.
- OfflineMotionEngine يظل مسؤولًا عن تخصيص إطارات المشهد والتحويلات الحركية المعتمدة.
- Motion Hub يرسل إلى المحرك موضع الكاميرا/اتجاهها/العدسة والحركة كأوامر تنفيذ، ولا يسمح للمحرك بإعادة كتابة الخطة الزمنية أو إسقاط مشاهد أو تقصير المدة.
- المدة النهائية ومعدل الإطارات وPTS وتزامن الصوت والفصول يملكها WOLF.
- إذا كان هناك تسجيل راوٍ معتمد وصالح، فإن مدته الفعلية هي المدة النهائية للفيلم؛ تتكيف خطة المشاهد والإطارات معها دون قص التسجيل. من دون تسجيل معتمد، تبقى مدة المشروع هي المرجع.
- المحرك يعيد إطارات أو طبقات أو مخرجات معلّمة بالتوقيت. WOLF Scene Compositor يوحّد الدقة والاتجاه والشفافية وترتيب العمق والألوان قبل تسليم الإطارات إلى خط الفيديو.
- يظل MediaCodec/MediaMuxer ومسار الصوت الحالي وفحص MP4 ونقاط الاستكمال هي جهة الإنهاء والإخراج المعتمدة.

### الحد الأدنى لعقد WOLF Scene Contract

كل طلب محرك يجب أن يحمل: `sceneId`، `shotId`، إصدار العقد، نطاق الإطارات، fps، الأبعاد، aspect ratio، أوامر الكاميرا والحركة، معرفات الأصول المعتمدة، ميزانية الموارد، ومحرك/Adapter المطلوب. وكل استجابة يجب أن تحدد: حالة التنفيذ، الإطارات/الطبقات الناتجة، PTS أو frame index، format/color space، alpha mode، الأبعاد، digest للمخرجات، استهلاك الموارد المقاس، وأسباب الفشل إن وجدت.

لا يُسمح بتمرير ملفات أو أصول لم تجتز WOLF Asset Registry، ولا تُعتبر صيغة GLB وحدها إثباتًا لصحة الخامات أو الهياكل أو التحريك؛ يجب اختبار كل خاصية يحتاجها المشهد.

## 6. حدود إثبات Filament الحالي

نجاح تشغيل GitHub Actions رقم 15 على commit `6bd005a7cb6d26514cb442d332039cfc66356c0b` يثبت تنفيذ الخطوات التالية بنجاح:

1. `./gradlew assembleDebug --stacktrace`
2. `./gradlew lintDebug`
3. العثور على `lib/arm64-v8a/libfilament-jni.so` داخل Debug APK
4. اختبارات JVM
5. خطوة اختبارات Android 12 التي تنفذ زر Filament التجريبي وتفحص MP4 الخمس ثواني

رابط السجل: https://github.com/WolfCodeS-sigma/WOLF-OFFLINE-VIDEO/actions/runs/45152511800

لكن هذا الاختبار يستخدم أصل GLB تجريبيًا داخل `app/src/debug/assets`، ويصدّر اختبارًا مستقلًا 1280×720 بمعدل 30fps ولمدة خمس ثوانٍ. مسار الاختبار لا يضيف الصوت (`requireAudio=false))، ولا يثبت تشغيل فيلم كامل أو مدته الطويلة، ولا يثبت أن Filament أصبح المحرك الافتراضي لـOfflineProductionEngine. زر الاختبار ظاهر في Debug فقط.

**تنبيه بناء مهم:** تبعيات Filament وكلاس `HorrorVideoExporter` موجودة حاليًا في source set/configuration العامين للتطبيق (`app/src/main` و`implementation`) وليسا محصورين بالكامل في `src/debug`. لذلك فإن إخفاء زر الاختبار عن Release لا يعني وحده أن مكتبات Filament مستبعدة من Release APK. لم يُجر فحص Release APK في هذه المرحلة؛ يجب حسم سياسة تضمينها وحجمها وتبعياتها في مراجعة الدمج الإنتاجي قبل اعتماد إصدار نهائي.

## 7. ضوابط الأداء والأمان

- لا تشغيل متزامن لمحركي 3D ثقيلين في اللقطة نفسها دون قياس وقرار صريح من Resource Guard.
- تنفيذ اللقطات الثقيلة بالتتابع وتحرير موارد المحرك بعد كل مهمة أو مجموعة لقطات قابلة لإعادة الاستخدام.
- لا تعتمد أرقام ذاكرة/حرارة/زمن افتراضية بوصفها حدود إنتاج. حدود Production تبقى PENDING حتى قياسها على الأجهزة المستهدفة؛ حدود الاختبارات الصناعية TEST_ONLY.
- يجب اختبار جميع المكتبات الأصلية للـABI المستهدف، وتعارضات Gradle/NDK، والتراخيص والاعتمادات الانتقالية قبل التضمين.
- Godot يدعم embedding داخل تطبيق Android، لكن وثائقه تنبه إلى دعم instance واحدة لكل process وإلى ضرورة إدارة تغييرات orientation/resize صراحةً: https://docs.godotengine.org/en/4.7/tutorials/platform/android/android_library.html
- يتطلب إغلاق Cocos إثبات مسار Creator Build/Make للمشروع الأصلي، وليس مجرد وجود كود native أو دعم Android المعلن: https://docs.cocos.com/creator/3.8/manual/en/editor/publish/native-options.html
- لا يدخل أي HDRI أو GLB تجريبي إلى مكتبة الإنتاج لمجرد أنه ظهر في POC. سجلا Debris Basement Corridor وAbandoned Hall 01 يظلان CANDIDATE إلى حين مراجعة الجودة والاستيراد والميزانية والنطاق والترخيص.

## 8. ما تم وما لم يتم في المرحلة 12

**تم في هذه المرحلة:**
- اعتماد توزيع الأدوار النهائي لكل محرك ومكوّن.
- فصل الأدوار المتداخلة بين Godot وFilament وlibGDX وKorGE وLottie.
- تثبيت WOLF Kotlin Core كمالك وحيد للجدول الزمني والصوت والتركيب والإخراج.
- توثيق حالات الجاهزية الفعلية والقيود، بما فيها حجب Cocos.
- تسجيل أثر تبعيات Filament العامة على فحص Release المستقبلي.

**ليس جزءًا من هذه المرحلة:**
- لا دمج جديد لمحركات في OfflineProductionEngine.
- لا تحويل زر Filament التجريبي إلى زر الإنتاج العادي.
- لا تغيير لملفات بيانات المشاريع أو checkpoints أو نظام الصوت أو صور المستخدم.
- لا إضافة أصول تجريبية إلى سجل الإنتاج.
- لا نقل تبعيات Filament إلى source set آخر في هذه المرحلة؛ تُترك سياسة Release للمراجعة الفنية المنفصلة.
- لا اختبار Realme 7/Mali-G76.
- لا بدء المرحلة 13 أو المرحلة 15.

## 9. شروط قبول الدمج الإنتاجي لاحقًا

قبل ترقية أي Adapter إلى الإنتاج، يجب أن ينجح جميع ما ينطبق عليه من: بناء Android وABI، اختبار rendered-frame فعلي على هدف Android، استيراد أصل معتمد، احترام Scene Contract، إثبات تحرير الموارد، قياس الذاكرة والحرارة وزمن الإطار/التصدير، دمج الإطارات مع Audio/PTS، regression tests لكل المراحل السابقة، وفحص Release APK وحجمه وتراخيصه. لا يكفي اجتياز POC منفردًا.

**قرار الإغلاق:** المرحلة 12 تحدد من يفعل ماذا داخل المنظومة، ولا تُحوّل أي محرك إلى إنتاجي تلقائيًا. يظل WOLF هو المدير والمخرج النهائي، والمحركات أدوات تنفيذ متخصصة تحت سلطته.
