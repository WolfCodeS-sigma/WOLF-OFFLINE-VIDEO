# تقرير توحيد واستعادة نواة WOLF OFFLINE VIDEO

تاريخ الإنشاء: 23 نوفمبر 2026

## 1. استراتيجية Git

- نقطة الانطلاق هي أحدث `main` الذي تمت قراءته عند بدء العملية: `a955907e4870de578b064249ab38e22953e9de52`.
- تم إنشاء فرع `integration/restore-unified-core` من `main`.
- لم يتم دمج تاريخ Phase 18 أو Stage 13 المتباعد. تُنقل الملفات المختارة إلى شجرة واحدة ويكون أول commit تكاملي أبوه `main` مباشرة.
- لا يُسمح بدمج POC محركات منفصلة أو تبعياتها إلى تطبيق الإنتاج ضمن هذه الخطوة.

## 2. قرارات توحيد الملفات

### ملفات Phase المعتمدة كأساس
- واجهة `MainActivity` مع الحفاظ على تسجيل الراوي البشري المجزأ والاستعادة والاعتماد.
- `WolfOfflineStoryAiEngine` ومكتبة المعرفة وبنية القصة.
- `WolfAudioMixer` بمعالجة Phase الصوتية، مع إضافة zero-padding من Stage حتى يطابق PCM مدة الفيلم المطلوبة.
- `WolfLongFilmEngine` و`WolfFilmProductionCoordinator` وحفظ اللقطات ونقاط الاستئناف.
- Offline runtime guard في Gradle والـManifest والتوثيق واختبارات Phase.

### ملفات Stage المعتمدة أو المدمجة
- `StoryDirectorEngine`: مالك تقسيم المشاهد وخطة اللقطات وتوزيع الإطارات وتوقيت الحركة والتكوين والإضاءة.
- `OfflineProductionEngine`: مسار الإنتاج الذي يستهلك خطة StoryDirector، مع توحيد إدخال الصور عبر `WolfSceneRenderPipeline`.
- `WolfSceneArtEngine` و`WolfProceduralMotionEngine`: نسخة البيئة والمؤثرات الجوية فقط، دون رسومات بشرية/أشباح هندسية.
- `WolfSceneDepthComposer`: حواجز `safeForParallax` وفحص bitmap مع حماية Canvas save/restore.
- `WolfSceneAssetStore`: رفع نسخة مخطط فصل العمق إلى الإصدار 2 لإبطال نتائج التخزين القديمة.
- `WolfMotionCodeLibrary` و`WolfSceneContract`: عقود محايدة للمحرك، ولا تعني اعتماد محرك خارجي.
- اختبارات StoryDirector وMotionCode وSceneContract ومسار fallback.

## 3. حدود الصور والرسوم الإجرائية

- لا توجد صورة مختارة: يستخدم التطبيق مسار البيئة الإجرائي. يرسم الخلفية الجوية والضباب والجسيمات والمطر والأغصان والمؤثرات البيئية المحدودة.
- لا يولّد المسار الإجرائي أشخاصًا أو أشباحًا أو وحوشًا أو أبوابًا أو أثاثًا أو مباني من أشكال هندسية بدائية. ذكر العنصر في القصة لا يعني أن التطبيق أنشأه.
- عند اختيار صورة، تبقى هي مصدر المشهد. عدم نجاح تحليل العمق لا يسمح بالرجوع إلى مشهد إجرائي؛ تُعرض الصورة ثابتة بلا zoom أو pan أو parallax.
- خوارزمية اللون/حدود الصورة ليست تحليلًا دلاليًا. `semanticValidationPassed` مغلق افتراضيًا، و`safeForParallax` لا يصبح صحيحًا بالثقة وحدها.
- إذا تعذر فك ترميز الصورة المختارة أو فشل رسمها فعليًا، يتوقف التصدير برسالة واضحة بدل استبدال محتوى المستخدم.

## 4. الصوت

- يحتفظ مسار الصوت بمعالجة Phase: high-pass وnoise gate وducking وحدود الراوي والمؤثرات.
- تمت إضافة zero-padding من Stage كي لا ينتهي ملف PCM قبل مدة الفيلم عند انتهاء مصادر الصوت مبكرًا.
- تبقى مقدمة الهوية قبل الراوي، وتُحسب المدة عبر `WolfCinematicAudioTimeline` مرة واحدة.
- لم يتم تنفيذ Android TTS في هذه الخطوة.

## 5. حدود POC

- تبقى Filament وGodot وlibGDX وLottie وKorGE وCocos في مسارات POC المعزولة ولا تُضاف إلى تبعيات تطبيق الإنتاج.
- لا يعلن هذا الدمج أن محركًا خارجيًا صار محرك الإنتاج الأساسي.
- لا يعلن هذا الدمج عن اجتياز Cocos أو اعتماد ميزانيات الأداء الإنتاجية دون دليل قياس.

## 6. خطة التحقق

1. فحص شجرة الدمج ومراجعة ملفات التكوين والواجهات.
2. تشغيل `verifyOfflineRuntime` وAndroid lint واختبارات JVM على commit التكامل.
3. معالجة أي فشل حقيقي في التجميع أو الاختبارات، ثم إعادة تشغيل المجموعة المتأثرة.
4. تشغيل مجموعة الانحدار الشاملة على نفس SHA بعد نجاح الإصلاحات.
5. التحقق من أن GitHub Actions تشير إلى SHA التكامل نفسه؛ لا تُنقل نتائج SHA قديم.
6. لا يُعلن APK أو اختبار هاتف فعلي ما لم ينتج فعليًا من بيئة مناسبة.
