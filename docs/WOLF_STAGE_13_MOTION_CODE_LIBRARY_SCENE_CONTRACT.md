# المرحلة 13 — بناء WOLF Motion Code Library وWOLF Scene Contract

**الحالة:** تنفيذ مكتبة رياضية محايدة عن المحرك وعقد بيانات موحد بإصدار 1.0.0  
**الأساس:** رأس المرحلة 12 على الفرع \`design/stage-12-final-engine-roles\`  
**حدود التنفيذ:** مكتبة بيانات وحسابات واختبارات JVM فقط؛ لا دمج محركات ولا تغيير لمسار إنتاج الفيديو.

## 1. ما الذي أُنشئ؟

### WOLF Motion Code Library

ملف \`WolfMotionCodeLibrary.kt\` يقدم واجهات مستقلة عن Android والمحركات:

- ساعة إطارات حتمية تعتمد FPS كسريًا وفهرس الإطار المطلق، وتحسب PTS بالميكروثانية دون استخدام ساعة الجهاز أو حسابات الوقت العشري.
- منحنيات Scalar وVector3 بمفاتيح مرتبة واستيفاء STEP وLINEAR وSMOOTHSTEP.
- عمليات Vector3 الأساسية، التطبيع، الضرب الاتجاهي/النقطي والاستيفاء.
- Quaternion للتطبيع والدوران والاستيفاء الكروي SLERP.
- Transform3 يطبق التحجيم ثم الدوران ثم الإزاحة بترتيب معروف.

كل المدخلات العددية تُرفض عند كونها غير منتهية، وتُرفض المنحنيات ذات المفاتيح غير المرتبة أو المكررة. سلوك العينة خارج المدى هو تثبيت قيمة أقرب طرف.

### WOLF Scene Contract

ملف \`WolfSceneContract.kt\` يعرّف:

- إصدار العقد، وهوية الطلب والمشهد واللقطة وبذرة صريحة.
- نطاق الإطارات المطلق وFPS الكسري.
- الأبعاد ونسبة أبعاد البكسل ونظام الإحداثيات ومصدر الصورة.
- أمر كاميرا اختياري وصفي لا يملك سلطة تغيير خطة اللقطة.
- طبقات مرتبة، وأنماط مزج وشفافية، ومراجع أصول ذات إصدارات وبصمات SHA-256.
- هدف Runtime محدد باسم وإصدار المحول والمحرك.
- حدود موارد موجبة ومحددة، مع GPU عند توفر قياسه.
- نتيجة تحتوي طبقات/إطارات وPTS وأبعادًا وصيغة ومساحة ألوان ونمط Alpha وبصمة SHA-256 ومرجع إخراج مبهمًا.
- مدقق طلب ونتيجة يرفض الإصدار غير المدعوم، والبيانات غير الصالحة، والإطارات المكررة أو الناقصة، وPTS أو الأبعاد المخالفة، والبصمات غير الصحيحة، والموارد التي تتجاوز حدود الطلب.

## 2. حدود الملكية التي لا تتغير

- \`StoryDirectorEngine\` يظل مالكًا لنية اللقطة وتكوينها وتوزيع ميزانية إطارات اللقطات.
- \`OfflineMotionEngine\` يظل مالكًا لتوزيع إطارات المشهد وحركة الكاميرا الحالية.
- WOLF Kotlin Core / Motion Hub يظل مالك مدة الفيلم وFPS والجدول الزمني وPTS والصوت والموارد والاسترداد والتركيب والتصدير.
- المحول لا يعيد كتابة القصة أو خطة اللقطات، ولا يغير عدد الإطارات أو PTS، ولا يقرر مدة الفيلم.
- مراجع الأصول في العقد ليست موافقة بحد ذاتها؛ يجب أن يمر الاستخدام الفعلي عبر WOLF Asset Registry وسياساته الحالية.
- لا تحميل DEX/JAR/SO أو سكربتات أو شيفرات ديناميكية من ملف العقد أو الشبكة.

## 3. ما لم تنفذه هذه المرحلة

- لا يوجد Adapter فعلي لأي محرك.
- لم يتم توصيل العقد بـGodot أو Filament أو libGDX أو KorGE أو Lottie.
- لم يتغير \`OfflineProductionEngine\` أو \`StoryDirectorEngine\` أو \`OfflineMotionEngine\` أو تنسيق المشاريع أو الأصول أو الصوت أو checkpoints أو MP4.
- لا يُعد تعريف Target لمحرك بعينه إثبات جاهزية ذلك المحرك أو اعتماده إنتاجيًا.
- لا يغير هذا التنفيذ أحكام Stage 12 حول Cocos وKorGE وSceneView أو حدود POC.
- لا يوجد اختبار هاتف حقيقي، ولا اختبار Realme 7.

## 4. اختبارات المرحلة

أضيفت اختبارات JVM تغطي:

1. استيفاء المنحنيات وحدودها ورفض المفاتيح المكررة.
2. عمليات المتجهات والدوران والتحويلات.
3. حتمية PTS لساعة الإطارات الكسرية.
4. قبول الطلب السليم ورفض نسخة العقد غير المدعومة.
5. رفض المعرّفات المكررة والأصول غير المشار إليها وحدود الموارد غير الصالحة.
6. رفض أوامر الكاميرا والجدول الزمني غير الصالحين.
7. مطابقة كل إطار مع نطاق الطلب وPTS والأبعاد وبصمة SHA-256.
8. رفض الإطارات الناقصة/المكررة والموارد المتجاوزة والمخرجات الجزئية عند الفشل.

**معيار النجاح:** اجتياز \`lintDebug\` و\`testDebugUnitTest\` دون تغيير اختبارات السلوك الحالية، مع بقاء كل الإنتاج الحالي غير متصل بالعقد الجديد حتى مرحلة دمج صريحة لاحقة.
