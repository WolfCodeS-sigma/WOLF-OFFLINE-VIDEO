الخطة الهندسية الرئيسية المحدّثة

منظومة طبقية تجمع التوليد الإجرائي بالأصول السينمائية الواقعية، ثم تربطهما بالمحركات عبر WOLF Motion Hub، وتنتهي بخط إخراج MP4 موحّد.

مرجع محفوظ — لا يبدأ التنفيذ قبل اكتمال مراجعة Debug وتوجيه المستخدم

1. القرارات الحاكمة

  • المستودع الوحيد: WolfCodeS-sigma/WOLF-OFFLINE-VIDEO.
  • الإنتاج Offline؛ لا بحث أو تنزيل أو تشغيل مولدات فيديو سحابية.
  • في مسار الصور، المستخدم هو من يختار ويرفع الصور. التطبيق يحللها ويفصل طبقاتها ويحرك العناصر المناسبة، ولا يختار صورًا بدلًا عنه.
  • مسار مستقل للموشن الهجين 3D/2.5D دون صور يرفعها المستخدم، يعتمد على الأصول المحلية والمولدات البرمجية.
  • مكتبة الأصول جزء من توزيع التطبيق نفسه، بلا ملف منفصل يطلب من المستخدم استيراده ولا تنزيل وقت التشغيل.
  • تشفير البيانات المحلية مؤجل. توقيع Release وتجهيز APK مؤجلان إلى بوابة الإصدار.
  • المستخدم وحده يحدد بدء المراحل؛ هذه الخطة لا تعني بدء التنفيذ. لا دمج أو تعديل main دون موافقته.

2. التشخيص المرجعي لفيديوهات Debug

هاتف الصحراء الزراعية

مسار بلا صور رفعها المستخدم، لكن المخرجات كانت مربعات ودوائر ومثلثات وألوانًا بدل بيئة سينمائية، مع شريط أحمر أعلى الفيديو وصوت مؤثرات منخفض. المطلوب أصول/بيئات محلية وتوليد إجرائي مقبول، ومنع UI overlay من دخول الفيديو.

صوفيا

الصور الـ32–34 اختارها المستخدم. العيب في تحليل الصور المختارة وفصل طبقاتها وتحديد ما يتحرك وفق المشهد، وفي حركة كاميرا عامة شوّهت الصور وظهور أشكال هندسية كأشباح. يجب حفظ الصورة الأصلية؛ وعند فشل الفصل تُستخدم حركة آمنة على الصورة كاملة، لا صورة بديلة ولا جسم هندسي.

الجاثوم

اختار المستخدم 11 صورة و30 ثانية وسجل تعليقًا مدته نحو 7 ثوانٍ. ملف MP4 المرفوع قيس بنحو 7.012 ثانية. يجب تتبع السبب في جدول اللقطات والإطارات وPTS ونهاية مساري الصوت والفيديو؛ المدة المختارة هي المرجع ولا ينتهي الفيديو مع تعليق أقصر.

3. المواصفات السينمائية الملزمة

لا أجسام هندسية بديلة

لا دوائر/مثلثات/مربعات بدائية كشخصيات أو أشباح. البديل المقبول: أصل سينمائي، silhouette مقصود، لقطة بديلة، أو الصورة الأصلية.

الشخصيات والبيئات

أجسام وخامات وإضاءة وظلال وRigging وتحريكات واقعية. المحرك وحده لا يولد بشرًا واقعيين من primitives.

الشريط الأحمر

فصل شريط تقدم الواجهة عن Render Target ومنع ظهوره في MP4.

العلامة المائية

شعار WOLF شبه شفاف بملمس دم سائل وقطرات متدلية، في موضع آمن لا يحجب الحدث.

الخط الدموي

كل النصوص والعناوين والتوضيحات داخل الفيلم بالهوية الدموية نفسها مع Arabic shaping وRTL وقراءة واضحة. واجهة التطبيق بخط عربي واضح عادي.

الصوت

مسارات منفصلة للراوي والجو والمؤثرات والموسيقى، مع LUFS/True Peak وCompressor وDucking وLimiter ومنع clipping.

سلامة الصور

حفظ الأصل والنسبة؛ لا تمديد أو تشويه للوجه أو الجسم. عند فشل الفصل، حركة محدودة وآمنة على الصورة كاملة.

المدة

targetDuration يحكم الإطارات والتصدير؛ تعليق 7 ثوانٍ لا ينهي فيلمًا اختيرت مدته 30 ثانية. لا قص تلقائي لتعليق أطول.

كل المحركات تبقى ضمن التصميم المطلوب، لكن إدخال Runtime كل واحد إلى APK يمر باختبار Android/ABI/NDK/Gradle/Graphics API والحجم والذاكرة. إذا تعذر الدمج المستقر، يتوقف هذا الجزء للمراجعة ولا يُفرض على حساب استقرار التطبيق.

  • لا تشغيل لجميع المحركات الثقيلة بالتوازي؛ تحميل عند الحاجة وتحرير الموارد بعدها.
  • البداية بتبادل إطارات/طبقات عبر مسار محدود الذاكرة وآمن. مشاركة GPU textures بين سياقات مختلفة تحسين لاحق فقط بعد إثباته.
  • Godot يدعم تضمين Android عبر AAR والتواصل ثنائي الاتجاه، لكن وثائقه تنبه إلى أن نسخة واحدة فقط من المحرك مدعومة في Android process، ويجب إدارة lifecycle/التدوير بعناية.

7. المكتبة داخل التطبيق والحجم

المستخدم لا يريد ملف مكتبة منفصلًا ولا استيرادًا يدويًا. المرجع هو أن تكون الأصول المعتمدة جزءًا من إصدار التطبيق، وتعمل دون اتصال بعد التثبيت.

  • في توزيع APK مباشر: تضمين الأصول المختارة داخل APK كـassets مع manifest مدمج.
  • إذا احتاج Runtime لمسارات ملفات، يستخرج التطبيق ما يلزم تلقائيًا إلى مساحة التطبيق الخاصة؛ هذا استخراج محلي داخلي لا حزمة مرافقة.
  • لا تنزيل شبكي ولا on-demand assets في المسار الأساسي.
  • يجب حساب مساحة التثبيت والنسخ المؤقتة والتحديث؛ لا نفترض أن حجم APK يساوي المساحة التي يحتاجها التثبيت دائمًا.
  • التقدير السابق 2–4 GB للحزمة الأولية مُلغى كهدف ثابت. نحدد الحجم من manifest حقيقي بعد الجرد والضغط والبناء.
  • تستخدم LOD وإعادة استخدام الخامات وضغطًا مناسبًا مثل KTX2 عندما يتوافق مع المحرك والجهاز، دون تدهور الواقعية.
  • Play Asset Delivery install-time جزء من APK set عند التثبيت ومتاح عند إطلاق التطبيق، لكنه ليس APK واحدًا ويتطلب قناة توزيع Play؛ لذلك ليس اختيارنا الافتراضي. لا نغيّر توزيع APK المباشر دون موافقة المستخدم.

  • شاشة اختيار المسار ببطاقات مستقلة، خاصة فصل مسار الهجين بلا صور عن مسار صور المستخدم.
  • مساحة عمل لكل مشروع ومحطات: القصة، المشاهد، الصورة والحركة، الصوت، الإخراج.
  • استوديو الصوت يعرض Teleprompter للنص كاملًا أثناء التسجيل، يميز السطر الحالي، تمرير يدوي/تلقائي، تكبير وتصغير الخط، المسافات والسرعة، مؤقت وموجة صوتية وإيقاف واستكمال وحفظ أجزاء.

10. الترتيب التنفيذي الأفضل

ترتيب تبعيات هندسي مقترح، لا يبدأ تلقائيًا. كل بوابة تتطلب مراجعة ونجاح الاختبار قبل التالية.

  1. إغلاق مراجعة Debug وجمع الأدلة: ربط كل عيب بملف/توقيت/إطار.
  2. تدقيق خط الإنتاج دون تغيير: رسم مسار القصة والمشاهد والصور والصوت والتصدير وتحديد مصادر الحقيقة.
  3. إصلاح المدة والتوقيت والتصدير: targetDuration وPTS وعدد الإطارات ونهاية muxer؛ اختبار 30 ثانية مع تعليق 7 ثوانٍ.
  4. تنظيف الرندر والـFallback: منع الشريط الأحمر والأجسام الهندسية البديلة.
  5. تحسين Storyboard Planner: ربط كل حدث بلقطة ومكان وشخصية وتوقيت واستمرارية.
  6. سياسة جودة وترخيص الأصول: معايير قبول ورفض وبيانات مصدر وتوافق.
  7. جرد WOLF Cinematic Asset Library: جمع مرشحين واقعيين مرخصين ومعاينة وتحريك وقياس الحجم.
  8. بناء Asset Registry & Quality Gate: فهرس وبصمات وصيغ وتبعيات ودرجات جودة.
  9. تصميم WOLF Procedural Generation Library: مولدات الهندسة والمواد والبيئات والمؤثرات وحدودها.
  10. اختبار تعاون المولدات والأصول: تخصيص قوالب واقعية مع حفظ الأصل والترخيص.
  11. POC منفرد لكل محرك: اختبار Runtime وABI/NDK/Gradle/Graphics API والحجم والذاكرة.
  12. اعتماد أدوار المحركات: تثبيت الدور الفريد لكل مكوّن وتوثيق أي تعارض قبل الدمج.
  13. بناء Motion Code Library وScene Contract: الأوامر المشتركة والمحوّلات.
  14. بناء WOLF Motion Hub: الجدولة والذاكرة والاختيار والبدائل والاسترداد.
  15. دمج المحركات تدريجيًا: Godot ثم Filament/SceneView ثم Cocos ثم libGDX ثم KorGE ثم Lottie، مع اختبارات رجعية بعد كل دمج.
  16. استكمال مسار صور المستخدم: segmentation والأقنعة والحركة الآمنة وحفظ الأصل وعدم التشويه.
  17. تطوير الهوية الدموية: الخط العربي لكل نصوص الفيديو والعلامة المائية شبه الشفافة.
  18. WOLF Audio Mastering: فصل المسارات والضغط وDucking وLimiter والقياس والمزامنة.
  19. إعادة تصميم الواجهة كاملة: مطابقة المرجع مع ربط الوظائف والملقّن واختبار RTL.
  20. اختبارات القصص المرجعية: هاتف الصحراء (بدون صور)، صوفيا (صور المستخدم)، الجاثوم (11 صورة/30 ثانية/تعليق 7 ثوانٍ).
  21. اختبار Realme 7: محاكي قريب ثم الجهاز الفعلي للحرارة والذاكرة والبطارية والتصدير.
  22. Release APK والتوقيع: مفتاح محفوظ خارج المستودع وبناء بعد الموافقة.
  23. التسليم والتوثيق: APK وأدلة الاختبارات والقيود.

13. مصادر تقنية رسمية

  • Godot Android Library — دمج Runtime كـAAR.
  • Godot Android Embedding — دورة الحياة والتواصل مع التطبيق المضيف وقيد instance واحدة للعملية.
  • Google Filament — Android PBR وOpenGL ES 3/Vulkan وواجهات Java/JNI.
  • SceneView — واجهة Android/Compose المبنية فوق Filament.
  • Cocos Creator Android native publishing.
  • KorGE — محرك Kotlin متعدد المنصات.
  • Lottie Android.
  • Play Asset Delivery — مرجع يوضح أن install-time pack جزء من APK set وليس ملف APK واحدًا.
  • Android bundletool.

المراجع لتصميم الدمج؛ تُراجع الإصدارات والتراخيص والتبعيات الدقيقة مجددًا عند مرحلة POC. لا يُفترض توافق جميع المحركات قبل البناء والاختبار.
